# 战斗脚本：配队、开战、循环出手、认结算

战斗脚本 = 导航（进玩法、选关、配队、开战）+ 一场战斗（看着画面出手直到结算）+ 记结果。导航部分和日常脚本一样写；这里只讲战斗那一段。
现成的引擎是 `tasks/2026-10-10-记忆战场/ma_battle.py` 的 `Battle`；同一个游戏的新玩法照 `tasks/2026-10-16-超弦空间/ss_battle.py` 继承它，只 import、不改原文件。别的游戏照它的结构自己写一个。

## 一场战斗的结构（`Battle`）

- 只在「看得到暂停键」（= 在战斗界面）时出手：暂停键用模板小图认（`tpl/pause.png`）。
- 一场 = 开局动作表（档案里的 `opening`）+ 通用循环（`loop`）：连点普攻，轮流试武器技、必杀、辅助技能，定时闪避、切人、接 QTE。
- 认结束：战斗界面消失约 3 秒后开始识字找结算页的字（「战斗失败」「挑战成功」「战斗得分」这类），之后约每 2 秒再认一次，25 秒还认不出就存图退出，不空等（`ma_battle.py` 开头注释写的 10 秒是旧数字，以 `loop` 里的代码为准）。
- 每场留证据：每秒一帧（`frames/`）、按钮亮度（`hud.csv`）、事件日志（`events.log`），放在 `logs.nosync/` 下；下一轮调阈值、调手法全靠它们。
- 给新玩法继承时常要覆盖的几处：开局等待（`wait_fight_start`）、结算页的字（`END_WORDS`）、QTE 判定（`qte_slot`）、有人倒下怎么办（`on_no_revive`）、要走路的关怎么认（`ss_battle.py` 的 `floor_check`）。

## 打法档案 `profiles/<id>.json`

一个敌人（或一个区）一份，照 `tasks/2026-10-10-记忆战场/profiles/` 里现成的写：

| 键 | 写什么 |
|---|---|
| `id`、`boss`、`difficulty` | 档案名、游戏里的名字、难度；脚本按名字加难度配档案 |
| `boss_idx` | 这个敌人在玩法页左栏的位置，从 0 数；训练入口（`--train`）靠它找到敌人，不写会直接报错 |
| `lineup` | 用哪支队：`tab` 是推荐阵容的页签（`"official"` 官方推荐，不写是 `"selected"` 精选推荐），`row` 第几行；`force: true` 时正式选人页已经配好队也照样按档案一键编队 |
| `team` | 三个人的名字或长相描述，按队伍顺序写全三个（只写一个，倒人后切人会乱） |
| `opening` | 开局动作表，一项一个动作：`["tap", 按钮]`、`["hold", 按钮, 秒]`、`["joy", dx, dy, 秒]`、`["switch", 第几个]`、`["qte", 最多等几秒, 没亮切谁]`、`["taps", 按钮, 次数, 间隔]`、`["wait", 秒]`。队伍里的人从 0 数：0 是开局在场的队长，1、2 是后两位 |
| `loop` | 通用循环的节奏：每轮普攻几下、武器技 / 必杀 / 辅助技能几轮一次、几轮闪避一次、几轮切一次人、追不追 QTE |
| `learned` | 学会的日期；`null` = 还没学会，正式打时不碰它 |
| `results` | 每场的结果（输赢、局内用时、得分、日志目录）。超弦空间按区打时 `ss_fight.py` 自动追加；记忆战场不自动写，学的时候自己记 |

## 学一个新敌人

1. 配队：先用游戏自带的推荐阵容（完整度优先、一键编队），别一开始就自己凑。档案最小可以照 `tasks/2026-10-10-记忆战场/profiles/moon.json` 抄，`learned` 先写 `null`。
2. 训练模式里打（不占次数、不锁人）：`opening` 先空着，只用通用循环；在 `tasks/2026-10-10-记忆战场/` 下跑 `../../bh3_auto/.venv/bin/python ma_battle.py profiles/<id>.json --train`，打完看 `events.log` 和每秒的帧，调闪避、切人、追不追 QTE。
3. 训练赢了再填 `learned`，正式打。正式打输了：同样的打法再试一次，还输再开增益之类的辅助选项。
4. 同一支队两次都没有明显提升，先换队（推荐阵容的下一行），别先改手法。
5. 某支队要特殊手法（按技能键的顺序、看头像认人）时，先录一段手打的示范：录屏加触摸记录，对着画面写成专属打法（例子 `tasks/2026-10-10-记忆战场/ma_style_fuhua.py`，档案里用 `style` 指过去）。

## 取帧和触控

- 普通截图一张要零点几秒到一秒，战斗里太慢：用 `bh3_auto/lib/frame_stream.py`（设备上 `screenrecord` 推流、电脑上 ffmpeg 连续解码、只留最新一帧）。要先 `brew install ffmpeg`。
- 按住、多指、边推摇杆边按键用 MaaTouch（minitouch 协议：`d` 按下、`m` 移动、`u` 抬起、`c` 提交、`w` 等待）。仓库里两个封装：
  - `bh3_auto/lib/maatouch.py`（乐土在用）：每次自己把程序推到设备、用完删掉。
  - `tasks/2026-10-10-记忆战场/touch.py`（记忆战场、超弦空间在用）：起进程前查设备上有没有 `/data/local/tmp/maatouch`，没有才推上去，推上去的留着下次用。
  - 不管用哪个，程序都得先在设备上：电脑上的仓库里有这个文件不算数，漏了「推到设备」这一步，新设备上一开战就起不来（v4.1.7 修的就是这个）。
- 没 root 的设备上用 `sendevent` 直接写触摸设备会被系统拒绝，别在这上面花时间。
- 整场战斗包在 `battle("正在战斗（…）")` 里：战斗中引擎不让暂停，会冒气泡说这一场打完再停。

## 坑

- 计时方向：有的玩法倒数（倒数走完人还活着也算失败，大招、转阶段会停表，一场真实时间可能远超面板上的时间），有的正数。照搬引擎前先核对开局：沿用「等倒数开始」会让正数计时的玩法每场干站十几秒。
- 亮背景、特效会被认成 QTE 光圈：判定时拿外圈对照（内圈亮、外圈不亮才算），短时间里接了太多次 QTE 就停几秒。
- 大招的全屏动画、演出选人画面里看不到暂停键：别当成战斗结束；有的演出画面要点一下才继续，认出来再点。
- 切到倒下的队友会弹「无法复活」并停住：点掉，记住倒下的人，之后不再切给他。
- 开战前有锁定确认框（「将被锁定…请确认」），只点带这几个字的框；一键编队之后窗口关得慢，等几秒再认选人页。
- 要走路、爬楼、找门的关：通用循环只会原地按键。先认出来（比如五个技能键都变成禁止图标），放弃这场并报「请手动打一次」，比空打到超时好。
- 识字会把战斗里的数字读错（剩余积分 180 读成 1160）：分数、进度这类读数和上一次比，明显不合理就重读。
- 设备几分钟不操作会息屏，息屏后第一下点击只把屏幕点亮：隔了一会儿再手动单打前，先截图看屏幕亮没亮。
- 玩法有结算期、准备期（结算中、准备中、未开放）：先认出来，只报状态、不打，别当成出错。
