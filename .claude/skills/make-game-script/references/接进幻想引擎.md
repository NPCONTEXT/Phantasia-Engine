# 接进幻想引擎：歌词、汇总、暂停、注册

脚本自己能跑通以后，靠这几样和幻想引擎对上：它打的几种行（引擎按行认进度和结果）、两个环境变量、暂停协议、`tools.json` 里的一条。
引擎这头的代码：认行在 `core/steps.py`（开头注释是全文），启动在 `core/runner.py`，勾选和角色在 `ui/session.py`，暂停在 `lib/play_ctl.py`（开头注释是全文）。

## 脚本要打的行

| 行 | 什么时候打 | 引擎拿它做什么 |
|---|---|---|
| `== 步骤名` | 每一步开始时（正好两个等号，`=== 横幅 ===` 不算） | 歌词跳到这一句；按文字相似度和 `tasks` 对上，对不上就按顺序取下一句 |
| `完成：步骤=结果，步骤=结果` | 最后一行 | 记进播放记录：结果是 `ok` 算做完，写别的就是没做完的原因 |
| `子项：A\|B\|C` | 读到本期名单时（只有带子项的歌） | 歌词里固定句后面的几句当场换成这几项 |

- 每行前面可以带 `[时:分:秒] `。结果文字里别带「=」；子项名字里别带「，」「=」「|」。
- 没做完的步骤，原因要写给人看的话（「没进到邮件页」「战令等级奖励没领完（页签还有红点）」），播放记录里直接显示它。
- 全做完返回 0，有没做完的返回 1（照现成的脚本）。
- 不分句、一直循环的脚本（乐土那种）不打 `==` 行：在 `tools.json` 的 `report` 里写正则，从它已有的输出里认 `stages`（到第几句）、`facts`（计数、抓数字，比如「第 3 层」）、`outcomes`（结束语，`bad` 标没达成）。照乐土那几首的写法。

## 两个环境变量

- `ANDROID_SERIAL`：引擎挑中的设备。启动引擎前自己设了它就只认它；否则按设备归并，上次用的那台优先、真机优先于模拟器，同一台设备插着线走线、没插线走无线调试（`core/env.py`「挑设备」那段注释）。脚本连设备时先读它，读不到才用写死的序列号：`os.environ.get("ANDROID_SERIAL") or "YOUR_DEVICE_SERIAL"`。
- `PLAY_CTL`：这次播放的暂停控制目录；`PYTHONPATH` 会带上 `lib/`，所以脚本里能直接 `from play_ctl import …`。

## 暂停（`lib/play_ctl.py`）

- 截图函数开头调 `pause_point()`：引擎要暂停、又不在战斗里，就停在这里，继续后重新截图；停过的时间会从计时里扣掉，等页面的超时不会因此提前到。
- 战斗包在 `with battle("正在战斗（…）"):` 里（也能当装饰器）：战斗中点暂停会被弹回，气泡说这一场打完再停。
- 每轮看一眼页面再动作的循环（乐土）用 `mark("…", say="…")` 标这一轮能不能停，`mark(None)` 解除。
- 不经引擎、单独运行时 import 不到，用什么都不做的替身（`play_ctl.py` 开头有现成的写法，照抄）。

## `tools.json` 加一条

照现成的抄一条改。日常脚本最少要这些：

```json
{
  "id": "mygame_daily",
  "name": "某游戏 · 日常",
  "album": "某游戏",
  "description": "签到 → 邮件一键领取。开播前游戏关着、或者停在主界面都行；不花付费货币。",
  "env": "none",
  "workdir": "tasks/2026-12-01-某游戏日常",
  "command": ["python", "mygame_daily.py"],
  "python": "../../bh3_auto/.venv/bin/python",
  "precheck": ["mygame_daily.py", "../../bh3_auto/.venv/bin/python", "../../bh3_auto/ocr/ocr"],
  "need_device": true,
  "tasks": ["签到", "邮件一键领取"],
  "report_steps": true,
  "package": "com.example.mygame"
}
```

| 键 | 写什么 |
|---|---|
| `id` | 唯一的英文名；日志文件名、播放记录、勾选状态都按它记，定了别改 |
| `name`、`album` | 歌名（「游戏 · 玩法」）和专辑（游戏名） |
| `description` | 界面「展开说明」里那段：完整流程、开播前游戏要停在哪、会花什么 |
| `workdir` | 工作目录，相对项目根 |
| `command`、`python` | 启动命令；写了 `python`（相对工作目录）就用它替换命令里的第一项 |
| `precheck` | 这首歌要用到的文件（相对工作目录）：脚本、解释器、识字程序；界面的「环境自检」逐首查它们在不在，缺了标红 |
| `env` | 开播前要不要切设备分辨率：`"none"` 不动；写成 `"2400x1504"` 这种就先切过去、结束还原 |
| `need_device` | 要不要设备在线才开播 |
| `tasks` | 歌词，一步一句，和脚本打的 `== 步骤名` 对上 |
| `report_steps` | 脚本打 `==` 行和 `完成：` 行时写 `true`，界面才按句显示进度 |
| `package` | 游戏的包名：顺序播放时引擎在开播前、结束后把游戏关掉（单独播放不关） |

可选的三样：

- 子项（一首歌里能勾的几项，比如本期三个敌人）：`"subitems": {"file": "本期名单.json", "head": [固定的几句], "arg": "--pick"}`。脚本把名单写进 `file`（`{"items": [{"label": "…"}, …]}`）并打 `子项：` 行；开播时引擎追加 `--pick 1,3`（一个没勾是 `--pick none`）。还没有名单文件时引擎不传 `--pick`：脚本这一次只读名单、做固定句，别开打。照记忆战场那首。
- 角色（只能选一个，比如乐土用谁打）：`"roles": {"arg": "--role", "default": "某个id", "items": [{"id": …, "label": …, "desc": …}]}`，开播时追加 `--role id`。
- `report`：见上面「不分句的脚本」。

改的时候注意：`tools.json` 是两个空格缩进、结尾没有换行；用程序读写时先确认原样写回和原文一字不差，改完 `diff` 只该多出新的那一条。改完重开幻想引擎，新歌就在歌单里。

## 每首歌结束以后

- 引擎截一张设备画面挂在这次的播放记录上，等你看一眼验收；脚本不用自己截。
- 日志在项目根的 `logs/`（每次播放一份）；脚本自己存的截图、战斗帧放工作目录的 `logs.nosync/`、`shots/`（`.gitignore` 已经排除）。

## 自己测

- 界面这头的测试在 `test_fake/`，用假脚本代替真游戏（`test_fake/fake_*.py`）。新歌接进来以后，可以照它们写一个按同样格式输出的假脚本，离线看歌词打勾、汇总、播放记录对不对。
- 新写测试、截图、演示脚本，第一件事把连设备的入口全换成报错或「没有设备」（脚本里的 adb、截图、点按，界面这头的 `env.adb`、`device_online`），外面再套一层禁止启动 adb 的沙箱：

```bash
sandbox-exec -p '(version 1)(allow default)(deny process-exec (regex #"/adb$"))' venv-qt.nosync/bin/python test_fake/你的测试.py
```

- 真歌别排进待播当摆设：要排就排假的，免得测试时真的开播。
