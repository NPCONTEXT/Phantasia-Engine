# 做一首歌：日常 / 战斗脚本

什么时候用：要给幻想引擎接一个新游戏，或者给已有的游戏加一个新玩法。
先读：README 的「先说清楚」「加一首自己的歌」；再在 `tasks/` 下挑一首最像的当底子，别从空文件写起。
两类：日常 = 认页面、点、点完核对，一步一句歌词；战斗 = 配队、开战、循环出手、认结算。细节在 `references/` 三份里（这几份写的路径都从项目根目录算）。

## 要准备的东西

- 设备：Android，打开 USB 调试或无线调试，`adb devices` 看得到。坐标按 2400×1504 写（竖屏游戏 1504×2400），现成的底层会按实际分辨率等比换算；比例不同时界面能临时切分辨率（`tools.json` 的 `env`）。
- 游戏：要做的玩法已经解锁；界面语言和脚本要认的字一致（现成的都是国服简体中文）。想清楚开播时游戏停在哪：顺序播放会先关掉游戏，脚本要能从冷启动一路走到主界面。
- 工具都在仓库里：截图 `adb exec-out screencap`；识字 `bh3_auto/ocr/ocr 图.png`（macOS 自带的 Vision，`./install.sh` 现编）；点按、滑动 `adb shell input tap/swipe`；长按、多指、边推摇杆边按键用 MaaTouch（`bh3_auto/lib/maatouch.py`）；战斗里要快就用 `bh3_auto/lib/frame_stream.py` 连续取帧；Python 环境 `bh3_auto/.venv`（OpenCV、NumPy）。
- 先写下来的规矩：要做哪几件事、每件做几次；哪些按钮花付费货币（一律不点，写进禁点名单）；体力、金币这类资源怎么花、花到什么时候停。脚本只照写下来的做，没写的不自己加。

## 流程

1. 建目录 `tasks/YYYY-MM-DD-名字/`，先写一页说明：做什么、不做什么、开播时停在哪、资源怎么花。
2. 侦察：手动走一遍，每一页截图，在页面笔记里记下坐标和「只有这一页有」的两三个字；弹窗、活动海报、签到、每天刷新、玩法没开放、结算中这些岔路也截下来。
3. 写脚本：底层（截图、识字、找字、点字、等页面、存图）照现成的抄；一步一个函数，进页面靠认字，每步从同一个起点出发、做完回到起点。日常看 `references/日常脚本.md`，战斗看 `references/战斗脚本.md`。
4. 一段一段实跑：一次只跑一步，盯着日志和截图，对上了再接下一步；整首连起来再跑几天，跨天、换期、活动上下线都碰一遍。
5. 离线测试放 `tests/`：用存下来的截图测认页面和读数，导航和战斗换成替身测流程；新写的用例先拿改之前的代码跑一遍，确认它会失败。
6. 接进幻想引擎：歌词行、汇总行、暂停、`tools.json` 注册、播放记录的事实和结束语，照 `references/接进幻想引擎.md`。
7. 收尾：歌的说明里写清每一步做什么、要什么前提、花什么；要记版本就三处一起改（`main.py` 的 VERSION、`tools.json` 的 app.version、`幻想引擎.app/Contents/Info.plist`），`docs/更新日志.md` 加一行。

## 最常踩的坑

- 识字会错（「剩余」读成「剥余」、数字丢一位、异体字）：认页面至少靠两个字，比文字用相似度，关键读数连着两次一样才信。
- 每个「点了就记成功」的步骤都要补「点完核对」：派遣没派出去、奖励没领到照样记 ok，是最常见的假成功。
- 页面上的东西会漂：页签、卡片、任务的顺序随活动和完成状态变，按字找位置，别写死坐标。
- 弹窗慢一拍：一键编队、领奖、开箱之后等几秒再认页面；收弹窗要连着两次都没认到才算收完。
- 同一步失败两次就停：存图、记「没做完」和原因、跳过这一步，别第三次换个花样硬试。
- 会开局、花体力、花货币的点按，先核对条件在当前画面真的成立再点。
- 调试时别把脚本丢到后台就走开：卡在不认识的画面会一直空等；一段一段在前台跑，看完截图再往下。
